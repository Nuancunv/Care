# ADR-002：首版暂不集成语音能力，语音作为后置附加选项

- **状态**：已确认（Accepted）
- **决策日期**：2026-11-25
- **相关模块**：`app/lib/`、`app/android/`、`plugins/care-bot/`

## 背景

语音识别（ASR）与语音合成（TTS）若在首版引入端侧离线模型（如 Sherpa-ONNX）会显著增加全量离线一体 APK 的体积与内存开销；若引入第三方云端语音 SDK 又会增加额外 API Key 配置门槛与外部依赖。同时，DeepSeek API Key 现已原生集成语音能力，未来具备零额外服务商接入的演进空间。

## 决策

1. **首版（M1 MVP）完全聚焦纯文本交互体验**（极简永续单线程对话、富交互卡片、透明 `SOUL.md`/`MEMORY.md`、主动简报），不启用语音输入、实时语音通话与 TTS 朗读。
2. **裁剪首版语音依赖**：在基于 `dsh-Go` 改造首版时，隐藏或剥离主界面的语音入口与相关权限申请（如 `RECORD_AUDIO`），保持权限最小化与包体精简。
3. **后置演进方向（M4+ / 附加选项）**：将语音定为可选增强模块，后续优先调研并复用 **DeepSeek API Key 原生集成的语音能力**，避免用户配置多套 API Key，保持 BYOK 单一密钥体验。

## 影响

- **正面**：首版聚焦核心 Agent 闭环、减少麦克风权限阻力、显著降低 APK 体积与功耗测试复杂度。
- **后续**：在架构与 UI 输入栏中保留语音按钮扩展槽位，方便后续以插件/开关形式平滑开启。
